## Objective

See the title and the audit sections above. State the goal in one sentence in
your own words before making any change.

## Scope

Every unauthenticated request to an admin route writes an audit row, and there is
no throttling of any kind, even though the 429 plumbing already exists.

Implement a rate limiter and stop writing an audit row for every anonymous
denial.

## Scope
1. Add a small rate-limiting helper in the `server/` tree.
2. Return HTTP 429 using the already-defined `rate_limited` error code, and set a
   `Retry-After` header.
3. Apply it to the `/api/admin/*` route family and to the admin-denial path.
4. Stop inserting a `session_denied` audit row for every anonymous request:
   aggregate, sample, or skip repeats.

## Non-goals
No change to the OAuth start route (4.2C). No caching (4.2D). No public query
bounds (4.2E). No schema change unless the audit analysis you write proves one is
required, and say so loudly if it is. Do not remove the `session_denied` action
entirely: it is genuinely useful for abuse investigation. Do not change how
authorization is decided.

## Implementation requirements
Read the audit sections above and the existing code before choosing a design. In
particular: an in-isolate `Map` is free and good enough for a single-admin site,
but it is per-isolate and therefore best-effort, so document that honestly rather
than overstating the protection. Whatever you choose, the 429 path must not be
possible to trigger by the single legitimate administrator during normal use.

## Required tests
- An anonymous burst against an admin route is rate limited with 429.
- Rate-limited requests stop writing audit rows beyond the sampling threshold.
- `Retry-After` is present on a 429.
- A legitimate administrator performing normal operations is never rate limited.
- The 50 pre-existing security tests still pass.
