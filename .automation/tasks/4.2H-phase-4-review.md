## Scope

Review the whole of Phase 4 before Phase 5 begins. This is a verification task,
not an implementation task.

## Scope
1. Re-measure every vector in the approved audit against the current code and
   state, for each one, whether it is closed, partially closed, or still open,
   with file and line evidence.
2. Re-run every gate in this roadmap task list and record the real results.
3. Confirm no regression was introduced anywhere in the application.
4. Write the findings into a new document under `docs/qa/`, and update the
   approved audit to record the outcome of each finding.
5. Recommend whether Phase 5 is safe to start, and on what conditions.

## Non-goals
Do not implement new features. Do not fix unrelated issues. Do not change
application behaviour to make a review finding look better. Do not deploy. If
the review finds a real defect, report it as a new roadmap task rather than
silently fixing it, unless it is a security issue, in which case say so
explicitly and explain the judgement.

## Implementation requirements
Base every statement on the code and on observed test output. Distinguish
confirmed from inferred. Do not claim a gate passed unless you ran it and saw it
pass. Measure the D1 operation counts before and after where you can, and report
the real numbers rather than an impression.
