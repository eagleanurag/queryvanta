## Objective

See the title and the audit sections above. State the goal in one sentence in
your own words before making any change.

## Scope

The bulk import is a sequential loop that can perform roughly fifteen hundred
D1 round trips in one request.

Batch it.

## Scope
1. Replace the per-item sequential loop with a batched write.
2. Remove the redundant existence pre-check where the unique primary key already
   enforces the invariant.

## Non-goals
No change to the import request cap or the request body cap. No change to the
outcome shape: the exact `{ imported, skipped, conflicts, failed }` result and the
per-item failure reporting must be preserved, because the client and the existing
tests depend on it. Do not overwrite an existing server-side question. No schema
change.

## Implementation requirements
This is the only Phase 4 task that changes write semantics, so it is the one most
likely to be wrong. D1 has a bound on the number of bound parameters per
statement; derive the batch size from what D1 actually supports and say what you
used. Preserve the "existing ids are skipped, never overwritten" guarantee that
the current code documents. Preserve deterministic ordering of the reported
failures.

## Required tests
- A 500-item import completes using a bounded number of D1 statements.
- The outcome counts match the previous implementation exactly for a mixed batch
  of new, duplicate and invalid items.
- An existing server-side question is never overwritten.
- Per-item failure reporting is preserved, in order.
- The pre-existing import test still passes unchanged.

## Required quality gates
```
npx tsc -b --force
npm run test:server
npm run lint
git diff --check
```

## Completion criteria
The import is batched, the observable outcome is identical to the sequential
implementation, and every gate passes with observed output.

## Stop conditions
Stop and report BLOCKED if you cannot preserve the exact outcome shape, or if
batching appears to change the never-overwrite guarantee.
