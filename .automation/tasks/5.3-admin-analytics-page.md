## Objective

See the title and the audit sections above. State the goal in one sentence in
your own words before making any change.

## Scope

Build the admin-facing view described in the 5.1 design document.

## Scope
The page, its route, and the aggregated read endpoint it needs.

## Non-goals
No change to the data model. No new collection. No change to the admin security
model. Do not weaken server-enforced authorization for the sake of the page: the
analytics read endpoint must require a valid administrator session exactly like
every other admin endpoint, and must not be publicly cacheable. No departure
from the 5.1 design.

## Implementation requirements
Reuse the existing admin patterns in the repository: the gate, the CSRF scheme,
the no-store response policy, and the shared catalog merge rules. Follow the
existing mobile and accessibility conventions, including the known accessibility
gap around unlabelled selects, so the new page does not add a new instance of
it.

## Required tests
The page renders for an administrator; it is unreachable without a session; its
endpoint is not publicly cacheable; it degrades honestly when there is no data
yet; and it is usable at the mobile viewport width.
