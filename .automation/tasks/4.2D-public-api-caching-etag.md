## Objective

See the title and the audit sections above. State the goal in one sentence in
your own words before making any change.

## Scope

The public read endpoints are explicitly uncacheable and have no client consumer,
so they are pure anonymous cost.

Make the public read path cacheable, and only that path.

## Scope
1. Serve the public question list and public question detail with a public cache
   policy and an ETag, including conditional-request handling.
2. Leave every other API response exactly as it is.

## Non-goals
This is the highest-risk task in Phase 4 for information disclosure, so the
non-goals are strict:
- Do NOT make any `/api/admin/*` response cacheable. Those responses contain
  unpublished drafts and the audit log.
- Do NOT make `/api/auth/session` cacheable. Its body contains the identity and
  the CSRF token; a shared cache would leak one administrator's CSRF token.
- Do NOT change any mutation response.
- Do NOT change the public visibility predicate in SQL. Caching is an addition
  here, not a way to avoid checking published state.
- No schema change.

## Implementation requirements
Choose a short TTL so that a publish or unpublish becomes visible quickly, and
say what you chose and why. Derive the ETag from a stable representation of the
response, not from a timestamp, so identical content produces an identical tag.
The existing security tests assert a consistent error envelope and draft
isolation; make sure caching does not make a draft reachable.

## Required tests
- The public list response carries a public cache policy.
- A conditional request with a matching ETag returns 304.
- Every `/api/admin/*` and `/api/auth/session` response still carries the
  existing no-store policy. Write an explicit test for this, not an assumption.
- A draft and a disabled question remain unreachable after caching is added.
- The 50 pre-existing security tests still pass.
