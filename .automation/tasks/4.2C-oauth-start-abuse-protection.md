## Objective

See the title and the audit sections above. State the goal in one sentence in
your own words before making any change.

## Scope

The OAuth start route performs an unauthenticated D1 insert on every call, and the
generic origin check does not apply to GET requests, so it is currently an
unauthenticated write amplifier.

Protect it.

## Scope
1. Require a verifiable same-origin signal on the OAuth start route. The generic
   mutation-only origin check is a no-op for GET, so this needs a route-specific
   check or a method change; decide from the code and justify it.
2. Apply the rate limit that 4.2B introduced.
3. Keep single-use, short-lived OAuth transactions and the existing state
   validation.

## Non-goals
No change to PKCE. No change to the callback's GitHub exchange. No schema
change. No change to the allow-list. Do not weaken or re-order the existing state
consumption logic, which is already correct.

## Implementation requirements
Do not break the legitimate flow: clicking "Continue with GitHub" from the app
must still work exactly as it does today. Whatever same-origin mechanism you use
must survive a normal browser navigation, which sends an `Origin` header only in
some cases. Read the audit section and the existing tests before choosing.

## Required tests
- A start request without a verifiable same-origin signal is rejected and
  inserts nothing into the transaction table.
- A legitimate same-origin start still creates a transaction and redirects.
- The rate limit applies to this route.
- Replay, unknown and expired state handling are unchanged: the existing
  OAuth tests still pass.
